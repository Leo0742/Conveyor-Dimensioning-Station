# Программно-аппаратный комплекс измерения габаритов товара на конвейере

**Болбачан Леонид Анатольевич**

## 1. Резюме решения

### Коротко о решении

- **Сенсор:** один двухкамерный лазерный профилометр LMI Gocator 2880.
- **Обработка:** локально на промышленном компьютере OnLogic Karbon K801.
- **Покрытие:** расчётный FOV 680 мм на верхней грани товара, по 40 мм запаса относительно ленты.
- **Сканирование:** целевые 1000 профилей/с; режим требует физической проверки на датчике или в Emulator.
- **Интеграция:** передача результата в WMS с локальной очередью при сбое сети.

Цель станции — оценить три стороны минимального по объёму охватывающего
прямоугольного параллелепипеда. Координата X идёт поперёк ленты, Y — по движению,
Z — вверх от плоскости ленты. Товар обнаруживает ретрорефлекторный датчик
SICK WLF4FI-973121A0ZZZ (далее WLF4FI). Инкрементальный энкодер
SICK DFS60I-BHPC65536 (далее DFS60) с мерным колесом должен подавать аппаратные
импульсы с целевым шагом 1 мм после проверки допустимой частоты профилей.
Gocator 2880 объединяет два взгляда на одну лазерную линию и передаёт метрические
профили по Gigabit Ethernet. OnLogic Karbon K801 локально выполняет калибровочное
преобразование, удаление ленты, фильтрацию, объединение профилей, оценку
minimum-volume OBB (minimal-approx),
контроль качества и доставку JSON в WMS.

В основном сценарии ML не требуется: между товарами около 3 с, а входной триггер
и отделение точек от плоскости дают естественную сегментацию. ML понадобится
только в том случае, если пилот обнаружит перекрытия, руки оператора, свисающую
упаковку или сложный движущийся фон.

Числа в документе разделены по происхождению:

- **По данным производителя** — официальная документация производителя;
- **Мой расчёт** — расчёт из опубликованных спецификаций и геометрии задачи;
- **Результат симуляции** — результат запуска данного прототипа;
- **Инженерная оценка** — оценка, которую надо подтвердить испытанием;
- **Физическое измерение** — зарезервировано для физического пилота; таких данных в проекте нет.

## 2. Требования и критерии приёмки

Исходный PDF [1] задаёт ленту 600 мм, скорость 1 м/с, средний интервал между
товарами 3 с, диапазон от 10×10×10 до 400×300×300 мм и погрешность каждой стороны
`±max(5 %, 5 mm)`. Форма и внешний вид произвольны. Результат передаётся в WMS.

| Параметр | Требование | Проверка проекта |
|---|---:|---|
| Ширина ленты | 600 мм | FOV 680 мм на Z=300 мм; запас 40 мм/сторону |
| Скорость | 1000 мм/с | целевой encoder spacing 1 мм; 1000 profiles/s требуют проверки |
| Поток | примерно 1 товар / 3 с | локальный цикл, очередь WMS вне измерительного пути |
| Минимум | 10×10×10 мм | ≈10 профилей по Y при целевых 1000 profiles/s и ≈12,7 samples по X |
| Максимум | 400×300×300 мм | MR=800 мм и зона Y=700 мм |
| Допуск | ±max(5%, 5 мм) | расчёт отдельно по каждой сортированной стороне |
| Геометрия | minimum-volume box | оценка minimum-volume OBB (minimal-approx) |
| Интеграция | WMS | PoC: JSON и локальная JSONL-очередь с дозаписью |

Для стороны 10 мм допустимо ±5 мм; для 100 мм — также ±5 мм; для 400 мм — ±20 мм.
Начальный инженерный ориентир может быть строже внешнего допуска, чтобы оставить
запас на дрейф, оптику, движение и алгоритм. Конкретный p95 не задан в исходном
задании и должен быть согласован с бизнесом после физического пилота.

## 3. Почему 2× Gocator 2490 не зафиксированы заранее

В предварительном варианте две головы 2490 могли казаться безопасным выбором
из-за широкого FOV. Для сравнения я проверил не только заявленное разрешение,
но и шаг точек в рабочей геометрии. У 2490 шаг меняется с расстоянием, одна камера
создаёт тень, а два независимых сенсора требуют временной синхронизации, общей
системы координат, сшивания зон перекрытия и контроля взаимного дрейфа.

Расчёт показывает, что широкий FOV 2490 не лишает его запаса дискретизации.
При требуемой геометрии у ленты получается
примерно 0,519 мм на точку, то есть около 19,3 отсчёта на 10 мм. Причина — 1920
точек в профиле [5]. Поэтому 2490 отклоняется не из-за недостаточной дискретизации,
а из-за одной камеры, избыточного MR=1525 мм, большей линейности в миллиметрах
и отсутствия необходимости покупать вторую голову.

## 4. Сравнение оборудования

### 4.1 Правила сравнения

Resolution (дискретизация), repeatability (повторяемость), linearity (линейность)
и absolute accuracy (абсолютная точность) — разные характеристики. Resolution
описывает минимальный шаг данных, repeatability — разброс повторов, а linearity —
отклонение усреднённой Z-позиции по MR. Ни один рассмотренный datasheet LMI не
публикует гарантированную абсолютную погрешность готовых L/W/H
после монтажа, движения, сшивки данных и алгоритма. Следовательно, соответствие
допуску нельзя доказать одной строкой datasheet: необходимы калибровочные объекты
с известными размерами и Gage R&R.

Для профилометра при скорости `v=1000 mm/s` продольный шаг равен
`ΔY = v / f_profile`. При 1000/800/500/380 Гц это соответственно
1,0/1,25/2,0/2,63 мм. Смаз равен `v × exposure`: при 1 мс — 1 мм. Scan rate не равен времени
экспозиции; последнюю надо подобрать на реальных тёмных и блестящих SKU.

### 4.2 Gocator 2880 — один двухкамерный профилометр

**По данным производителя.** Актуальная официальная страница LMI описывает
2880 как двухкамерный лазерный профилометр с 1280 точками на профиль [3]. Datasheet
rev. 2.3 даёт FOV 390–1260 мм, X resolution 0,375–1,1 мм, Z resolution
0,092–0,488 мм, MR 800 мм, clearance 350 мм, Z linearity ±0,04% MR, scan rate
380–5000 Гц, encoder и trigger inputs, Gigabit Ethernet [4]. Отдельная repeatability
в этом datasheet не приведена.

**Мой расчёт.** Линейная интерполяция FOV по factory range используется только
для предварительной компоновки:

`FOV(z)=390+(1260−390)×z/800`.

Для 40 мм бокового запаса принят FOV 680 мм на верхней поверхности товара.
`z_top≈266,67 мм`. Центр сенсора находится на
`350+266,67+300≈916,67 мм` над лентой. Плоскость ленты лежит на
`z≈566,67 мм`, где FOV≈1006,25 мм. Худший X pitch
`1006,25/1280≈0,786 мм`, то есть 10 мм занимают ≈12,72 отсчёта. На вершине
pitch≈0,531 мм. При целевом 1 мм encoder spacing имеется около 10 профилей вдоль
10-мм объекта. MR оставляет около 233,33 мм после уровня ленты. Z linearity
±0,04%×800 = ±0,32 мм — это linearity, не абсолютная accuracy.

1000 profiles/s — **целевая частота**, а не физически проверенная конфигурация. Официальные материалы
LMI объясняют, что максимальная частота зависит от active area, exposure и
subsampling, рассчитывается Trigger panel, а слишком частые encoder triggers
приводят к trigger drop [26–29]. Official desktop Emulator потребовал LMI account
и Windows package; на текущем macOS ARM host его расчёт честно не получен.

| Частота | Шаг Y | Профилей на 10 мм | Вывод для min SKU |
|---:|---:|---:|---|
| 1000 Гц | 1,00 мм | 10 | целевой хороший запас; требует Emulator/hardware check |
| 800 Гц | 1,25 мм | 8 | рабочий запас сохраняется |
| 500 Гц | 2,00 мм | 5 | погранично для устойчивых границ |
| 380 Гц | 2,63 мм | 3,8 | запас недостаточен для уверенного измерения |

До одобрения оборудования надо зафиксировать окончательные ROI/exposure и
подтвердить 1000 Гц в Gocator Emulator либо на физическом 2880. Если режим не
достижим, следует сначала проверить 800 Гц физически, а не молча сохранять шаг 1 мм.

Две внутренние камеры видят одну лазерную линию с противоположных сторон и
уменьшают затенение от вертикальных стенок. Один корпус не требует внешней
синхронизации и взаимной калибровки двух голов. Верхняя система всё равно не
видит дно и глубокие поднутрения.

### 4.3 Gocator 2490 — одна или две головы

**По данным производителя.** Для 2490 опубликованы 1920 точек/профиль,
FOV 390–2000 мм, X resolution 0,25–1,1 мм, clearance 350 мм, MR 1525 мм,
Z linearity ±0,04% MR, repeatability 0,012 мм и 370 Гц на полном поле;
официальная продуктовая страница отдельно приводит 800 Гц для области 1×2 м
и до 5000 Гц [5, 6]. В используемом англоязычном datasheet отдельная строка
Z resolution не приведена; официальный японский datasheet LMI указывает
Z resolution 0,06–1,5 мм [30].

**Мой расчёт.** Для FOV=680 мм на Z=300 мм `z_top≈274,69 мм`; высота
≈924,69 мм. На ленте FOV≈996,72 мм, pitch≈0,519 мм и ≈19,26 отсчёта
на 10 мм. При 800 Гц
продольный шаг 1,25 мм, около восьми профилей на 10 мм. MR покрывает 300 мм с
большим избытком. Z linearity в абсолютных единицах равна ±0,61 мм, тогда как
repeatability 0,012 мм; эти значения нельзя складывать или выдавать за accuracy.

Одна голова даёт один ракурс и выраженную тень. Две противоположные головы
уменьшают её, но требуют Sensor Networking/Master, синхронизацию до 1 мкс,
распределение сигнала энкодера и внешнюю калибровку [9]. Цена и число отказных точек примерно
удваиваются; прозрачность остаётся проблемой. Поэтому 1×2490 — сильный запасной
вариант, а 2×2490 для данной геометрии неоправданны.

### 4.4 Три Gocator 2450 — узкое поле

**По данным производителя.** Gocator 2450 имеет 1800 точек/профиль,
FOV 145–425 мм, X resolution 0,10–0,255 мм, clearance 270 мм, MR 550 мм,
Z linearity ±0,01% MR, repeatability 0,002 мм и до 5000 Гц [7, 8].

**Мой расчёт.** Одна голова не покрывает 600 мм. Двух также недостаточно:
чтобы плоскость ленты оставалась в MR при высоте товара 300 мм, верхний срез
можно поставить не дальше 250 мм в MR; там FOV≈272 мм, две головы дадут ≈545 мм
даже без перекрытия. Практически нужны минимум три головы, каждой около 220 мм
полезного поля с перекрытием. Дискретизация >39 отсчётов на 10 мм, linearity
±0,055 мм — существенно лучше нужного, но сшивание трёх систем, направленные
тени и высокая цена не окупаются допуском 5 мм.

### 4.5 Две RealSense D457 — активное стерео

**По данным производителя.** D457 имеет global shutter, 1280×720 depth,
до 90 fps, FOV 87°×58°, ideal range 0,6–6 м, minimum depth 0,52 м и заявленную
depth accuracy <2% на 4 м [11]. Производитель документирует аппаратную
синхронизацию нескольких D457 и особенности overlapping depth cameras [12, 13].

**Мой расчёт и инженерная оценка.** При монтаже камеры примерно в 0,8 м над
лентой поле на плоскости ленты ≈1518 мм, то есть ≈1,19 мм/pixel и ≈8,4 pixels
на 10 мм. Верх 300-мм товара находится уже примерно в 0,5 м: геометрическое
поле там ≈949 мм, но расстояние чуть меньше опубликованного Min-Z ≈0,52 м.
Следовательно, расчёт на 0,8 м нельзя переносить на весь рабочий объём; высоту
и качество глубины пришлось бы валидировать отдельно. При 90 fps объект проходит 11,1 мм между
кадрами; нужна точная фаза триггера, а для min-size нет продольной избыточности.
Две диагональные камеры сокращают слепые зоны, но требуют объединения карт глубины.
Опубликованная характеристика <2% на 4 м не является гарантией ≤5 мм для всей
измерительной станции в нашем рабочем диапазоне. Поэтому соответствие требованию
`±max(5%, 5 мм)` нельзя доказать по публичной спецификации D457. Активное стерео
чувствительно к слабой или повторяющейся текстуре, внешнему ИК-излучению, чёрным, бликующим и
прозрачным поверхностям. Вариант пригоден для недорогого лабораторного PoC, но не выбран.

### 4.7 Закупка, сервис и резервная архитектура

Точные цены и сроки не фиксируются без коммерческого предложения. Для 2880 и
2490 доступна единая промышленная экосистема Gocator и поддержка LMI/дистрибьютора;
для одного 2880 нужна одна запасная голова, а пара 2490 увеличивает число узлов,
синхронизацию и объём повторной калибровки. Три 2450 имеют повышенный риск замены
из-за трёх согласованных каналов. D457 доступен как промышленная стереокамера,
но требует совместимого GMSL host/deserializer и драйвера [11]. Во всех случаях
наличие, срок и локальный сервис надо подтвердить у поставщика.

Если 2880 недоступен, первый fallback — один 2490 при приемлемых тенях на пилоте;
если пилот подтвердит недостаточную видимость — два синхронизированных 2490.
Замена сенсора требует новой калибровки и MSA, а не только пересчёта FOV.

Чёрная матовая поверхность уменьшает отражённый сигнал, глянцевая может дать
насыщение и пропуски из-за бликов, а прозрачная — вернуть фон или несколько поверхностей. У 2880
две камеры повышают вероятность валидного отражения, но не решают физику материала.
Для рабочей линии нужны настройки экспозиции, ограничения мощности, матовый фон ленты
и контроль полноты данных; прозрачный товар при недостаточной полноте отправляется
на ручной поток.

### 4.8 Официальное применение 2880 для упаковки

Выбор 2880 основан не только на таблице характеристик. В официальном анонсе LMI относит
его к упаковке и крупным сложным формам, подчёркивая две камеры для уменьшения
окклюзий [23]. В официальном кейсе Box Void Fill Measurement Gocator 2880
измеряет внутренний объём высоких коробок; два взгляда помогают видеть зоны,
которые закрывались бы одной камерой [24, 25]. Для задания важны те же физические
свойства: двухкамерная триангуляция, FOV, MR, частота сканирования,
энкодер/триггер, Ethernet и дискретизация. Gocator 2490 прямо позиционируется
для логистики и остаётся допустимым запасным вариантом, но его единственная
камера сильнее затеняет произвольную форму.

## 5. Финальная физическая компоновка

Все координаты этого раздела — **предварительный расчёт компоновки**. 680 мм FOV на
верхнем уровне оставляет 40 мм запаса с каждой стороны 600-мм ленты. Заводская
модель конкретного датчика и механические допуски должны уточнить координаты.

![Рисунок 1. Размещение оборудования, вид сбоку](../assets/diagrams/layout_side.png)

Сенсор предлагается установить по центру поперечной балки примерно в 916,7 мм над верхней
поверхностью ленты; лазерная линия ориентирована вдоль X. Товар движется по Y.
Расчётная зона накопления длиной 700 мм включает максимальные 400 мм товара и
запас до/после. WLF4FI стоит за 250 мм до начала зоны: при 1 м/с это 250 мс на
создание контекста item_id, проверку состояния системы и подготовку буфера. DFS60 контактирует
с лентой мерным колесом; конкретный диаметр выбирается так, чтобы целочисленное
деление импульсов дало 1 мм и не превысило 820 кГц [14].

WLF4FI пока является проектным выбором, а не доказательством обнаружения
10×10×10 мм. Его официальный datasheet указывает точечный ИК-луч и пятно около
Ø40 мм на 1 м [16]; результат зависит от расстояния, рефлектора, положения и
отражательной способности товара. Минимальные матовые, чёрные, блестящие и
прозрачные SKU надо проверить на стенде. Возможные fallback — другая геометрия
фотоэлектрического датчика, меньший spot, световая завеса или presence-логика
по PLC/потоку профилей. Без этой проверки надёжность триггера не заявляется.

![Рисунок 2. Размещение оборудования, вид сверху](../assets/diagrams/layout_top.png)

Кожух исключает доступ к лучу класса 3R и паразитную засветку; блокировка отключает
лазер при открытии. Механика должна иметь жёсткую базу, виброустойчивое крепление,
защиту окна и сервисный доступ. Финальные 916,7 мм нельзя переносить на монтаж без
заводской калибровочной модели: формула использует линейную интерполяцию крайних FOV.

Калибровка включает: (1) заводскую модель профиля; (2) преобразование координат сенсор → лента;
(3) плоскость Z=0 по калибровочной плите; (4) масштаб энкодера и направление; (5) задержку
от триггера до получения профиля; (6) проверку по сертифицированным блокам в центре и краях FOV.
Все функции PoC предполагают уже калиброванные координаты: X поперёк ленты,
Y по движению, Z по нормали, а плоскость ленты находится около Z=0. Произвольные
некалиброванные мировые координаты не поддерживаются.

## 6. Вычислитель и интерфейсы

Предлагаемая конфигурация OnLogic Karbon K801: промышленный безвентиляторный компьютер с
процессором класса Core i5 мощностью 35 W, 32 GB RAM, 1 TB NVMe и двумя 2.5GbE [17]. Платформа
конфигурируемая; эти память и накопитель — проектная комплектация, а не единственный
заводской вариант. Один порт выделяется сенсору, второй —
сети OT/WMS; питание и сторожевой таймер подключаются к шкафу управления. Для одного
товара на CPU нужно построить выпуклую оболочку нескольких тысяч точек и перебрать ориентации;
GPU не требуется.

Альтернативы: компактный обычный x86 дешевле, но хуже по температуре, вибрации

контура из-за сети, задержки и потери управления при сбое. Облако допустимо для агрегированных
метрик и переобучения.

## 7. Алгоритм рабочей станции

1. WLF4FI создаёт событие товара и связывает его с `item_id` от PLC/WMS.
2. DFS60 должен аппаратно задавать Y каждой лазерной линии с целевым шагом 1 мм;
   этот режим включается только после проверки доступной частоты и пропусков триггеров.
3. Gocator 2880 формирует метрические X-Z профили из двух камер.
4. Заводская модель и внешняя калибровка переводят точки в координаты ленты.
5. Плоскость ленты оценивается при пустой ленте и затем контролируется с помощью RANSAC.
6. Точки ниже минимальной высоты удаляются; выбросы фильтруются по соседям.
7. Радиус кластеризации я выбираю автоматически по расстоянию между соседними
   точками и ограничиваю диапазоном 2–20 мм. Мелкие шумовые компоненты
   отбрасываются; близкий фрагмент соединяется только если он не больше 20%
   соседнего компонента. Два близких сопоставимых компонента не сливаются;
   два кластера размером не менее 20% крупнейшего дают `object_overlap`.
8. Профили объединяются по координате Y от энкодера. Модель `AcquisitionBatch`
   задаёт границу будущего адаптера: точки, позицию/шаг энкодера, полученное и
   ожидаемое число профилей, пропуски/невалидные профили, valid fraction,
   status flags, trigger drop и необязательную долю saturation. Реального драйвера
   и аппаратных значений в PoC нет; обычный вход `points_mm` сохраняется.
9. Строится оценка minimum-volume OBB (minimal-approx): устойчивое направление
   оценивается по доминирующей верхней плоскости. Дополнительно считается OBB
   по выпуклой оболочке. Если два способа дают слишком разные размеры, результат
   помечается как ненадёжный.
10. Размеры OBB сортируются `L≥W≥H`, проверяются диапазон и некалиброванный
    эвристический показатель качества. Эти имена означают порядок рёбер, а не
    оси конвейера. Отдельно компоновка ограничивает физический вертикальный Z
    значением 300 мм. Если production WMS требует `height_mm=Z`, нужен явный
    контракт преобразования, который может отличаться от сортировки PoC.
11. В PoC только окна со статусом `ok` входят в медиану и MAD по каждой стороне.
    Итог `ok` требует минимум 3 таких окна, не менее 50% валидных окон и
    `MAD_axis ≤ max(2,5 мм; 2,5% × median_axis)`. Иначе при наличии геометрии
    возвращается `low_confidence`; если валидных окон нет —
    `insufficient_depth_data`. Невалидные окна не участвуют в численной медиане.
12. PoC сохраняет сообщение в локальной JSONL-очереди, куда записи только добавляются; ограниченная
    очередь, подтверждение доставки и повторы относятся к будущей рабочей системе.

Псевдокод обработки одного товара

```text
on item_trigger(item_id):
    profiles = collect_until_trailing_gap(verified_encoder_step)
    cloud = calibrate_and_merge(profiles)
    plane = validate_belt_plane(cloud)
    components = observed_density_clusters(filter(remove_plane(cloud, plane)))
    if two_significant_components(components): emit(object_overlap, no dimensions)
    object = one_significant_component(components)
    if quality_failed(object): emit(status, no trusted dimensions)
    else:
        object += project_lowest_contact_band_to_plane(object)
        hull = convex_hull(object)
        box = dominant_top_plane_obb_or_face_edge_fallback(hull)
        if obb_disagreement(box, face_edge_obb(hull)) > 25%: emit(low_confidence)
        result = median_if_count_fraction_and_mad_pass(valid_window_boxes)
        deliver_or_enqueue(wms_message(item_id, result))
```

## 8. Почему оценка minimum-volume OBB (minimal-approx), а не AABB или PCA OBB

AABB привязан к осям конвейера: поворот прямоугольной коробки на 45° увеличивает
X/Y envelope. PCA находит направления максимальной дисперсии, но не минимизирует
объём; он нестабилен у симметричных и неполных поверхностей. Требование задания —
минимальный охватывающий прямоугольный параллелепипед.

Основной способ оценивает ориентацию по доминирующей верхней плоскости и ищет
прямоугольник минимальной площади в этой плоскости. Дополнительно считается OBB
по выпуклой оболочке через `scipy.spatial.ConvexHull` [20]. Для граней и рёбер
перебираются ортонормированные системы координат, после чего выбирается наименьший
из найденных объёмов. Если два способа дают расхождение больше 25%, результат
получает статус `low_confidence`.

Для независимой проверки я сравнил результат с Open3D 0.19.0 на коробках,
L-образной фигуре, цилиндре и нескольких нерегулярных объектах. Метод
`create_from_points_minimal` в этой версии Open3D тоже даёт приближённый
результат; точный `MINIMAL_JYLANKI` здесь недоступен [18, 22]. Поэтому я не
называю ни один из результатов математически точным minimum-volume OBB.

Оценка контакта с лентой — отдельная эвристика. На плоскость проецируется
только нижняя полоса (1-й процентиль), а не весь силуэт. Это помогает коробчатым
объектам оценить контакт и не раздувает наклонённый силуэт. Эвристика не
восстанавливает произвольное дно; ножки, полости, мягкая упаковка и невыпуклые
поднутрения остаются источником неопределённости.

Поскольку в задании требуется именно параллелепипед минимального объёма, перед физической приёмкой я бы отдельно проверил ошибку этого приближения на точной или эталонной реализации OBB. Если эта ошибка заметно влияет на требуемый допуск, приближённый алгоритм нужно заменить.

## 9. Роль ML и план данных

В основном алгоритме нейросеть не нужна. Если на реальной линии появятся руки
оператора, второй товар, свободный пакет или сложный фон, я бы добавил RGB-камеру
и сегментацию объектов (instance segmentation). Основной класс — `product`, дополнительные отрицательные
классы — `person/hand`, `conveyor_fixture` и `foreign_object`. Маска нужна
только для выбора соответствующих 3D-точек; размеры всё равно вычисляются
геометрически.

Для пилота потребуется примерно 12–15 тыс. размеченных кадров или профильных
проекций: не менее 2 тыс. трудных примеров (чёрный, глянец, прозрачность, тонкие
пакеты, край FOV), 2 тыс. сложных отрицательных примеров и проходы SKU в разных yaw.
Разделение 70/15/15 выполняется группами по SKU, дню и линии, чтобы один экземпляр
не попал одновременно в обучение и тест. Аугментации включают яркость, шум,
смаз по движению, пропуски полос, частичную окклюзию и замену фона. Геометрический
масштаб нельзя менять без согласованного преобразования depth.

Стартовая модель — компактная YOLOv8m-seg, потому что практический кейс Ozon Tech
описывает переход к YOLOv8m-seg и более 15 тыс. изображений [2]. Это отраслевой
ориентир, не результат данного проекта. Метрики: mask mAP50-95, recall трудного
среза, доля ложных объединений/разделений и, главное, доля корректных измерений.
Экспорт через ONNX/TensorRT имеет смысл только после подтверждения необходимости;
геометрический расчёт на CPU остаётся основным.

## 10. WMS и эксплуатационная надёжность

JSON содержит `measurement_id`, `item_id`, время UTC, `length_mm`, `width_mm`,
`height_mm`, `confidence`, `measurement_status`. `confidence` — некалиброванный
эвристический показатель, а не вероятность правильности. `measurement_id`
стабилен для пары товар/время и используется для защиты от повторной записи. Пример:

```json
{
  "measurement_id": "36918523-5216-5204-acbf-cfde7c82fbdc",
  "item_id": "synthetic-demo-001",
  "timestamp": "2026-09-09T12:00:00Z",
  "length_mm": 120.781,
  "width_mm": 80.736,
  "height_mm": 45.966,
  "confidence": 0.968,
  "measurement_status": "ok"
}
```

**Реализовано в PoC:** схема сообщения, детерминированный `measurement_id`,
обязательное timezone-aware время с сериализацией UTC `Z`, локальная
JSONL-очередь и модульные тесты. Неоднозначный naive datetime отклоняется.

Для любого `measurement_status != "ok"` публичный WMS JSON передаёт
`length_mm = width_mm = height_mm = null`: внутренние диагностические размеры
не представляются как доверенные измерения. Идентификаторы, время, показатель
качества и статус сохраняются.

В реальной системе сообщение можно отправлять в WMS по HTTPS (при необходимости
с mTLS). Если WMS временно недоступна, результат должен остаться в локальной
очереди и отправиться повторно. Для внедрения также понадобятся аутентификация,
ограничение числа повторов, подтверждение доставки и контроль переполнения
очереди. Статус `wms_unavailable` относится к этому будущему транспортному слою
и не формируется текущим PoC.

## 11. Ошибки и защитное поведение

### Основные отказы

| Сбой | Детектор | Поведение |
|---|---|---|
| нет/мало точек глубины | число точек / отсутствие кластера | `insufficient_depth_data`, ручной поток |
| два товара | два сопоставимых кластера | `object_overlap`, не объединять размеры |
| объект вне диапазона | границы OBB/FOV/MR | `measurement_out_of_range` |
| дрейф/вибрация | отклонение контрольной плоскости | `calibration_error`, останов/перекалибровка |
| мало/плохая повторяемость окон | count/fraction и MAD по L/W/H | `low_confidence`, размеры не доверять |
| прозрачность/глянец | будущий контроль пропусков и насыщения | повтор с другой экспозицией или `low_confidence` |
| энкодер проскальзывает | расхождение скорости по данным PLC | отклонить результат, сервисное предупреждение |
| WMS недоступна | тайм-аут / 5xx | локальная очередь, подтверждение и повтор |
| персонал в зоне | световая завеса / блокировка | отключить лазер/остановить измерение |

### Статусы PoC

| Статус | В PoC | Триггер | Что добавить в рабочей системе |
|---|---|---|---|
| `ok` | да | один кластер, эвристический показатель качества прошёл проверку | калибровка confidence по физическому пилоту |
| `insufficient_depth_data` | да | нет измеримого кластера | другая экспозиция или ручной поток |
| `object_overlap` | да | ≥2 значимых кластера | разделение потока через PLC |
| `measurement_out_of_range` | да | OBB выше диапазона с допуском | проверка границ FOV/MR |
| `low_confidence` | да | <80 точек, расхождение OBB >25% или aggregate count/fraction/MAD | пороги проверить на физическом пилоте |
| `calibration_error` | частично | не найдена доминирующая плоскость | контроль калибровочного объекта |
| `wms_unavailable` | нет | только будущая передача | повтор и подтверждение |

Оптически невидимый выступ, дно и глубокая впадина принципиально не восстанавливаются
надёжно из верхнего вида. Если данных недостаточно, система должна отказаться от
измерения, а не выдавать сомнительный результат. Для
постоянного измерения полностью прозрачной упаковки нужен отдельный физический
канал (например, световая завеса или несколько силуэтных камер), новое сравнение
оборудования и новая MSA.

## 12. Прототип и тестирование

В прототипе я использовал NumPy, потому что облако точек удобно хранить и
обрабатывать как числовые массивы. SciPy нужен для KD-tree и ConvexHull: через
них выполняются поиск соседей и построение выпуклой оболочки. Pydantic проверяет
структуру сообщений, передаваемых в WMS. Matplotlib и Pillow используются только
для визуализации демо, а ReportLab — для воспроизводимой сборки PDF-отчёта.
Open3D не входит в обязательные зависимости основного алгоритма: он нужен только
для независимого сравнения OBB.

Основной генератор помечен как **упрощённая симуляция лазерного профилометра**. Число точек не
задаётся произвольно: шаг X вычисляется из FOV профилометра на номинальной верхней
высоте объекта и 1280 отсчётов на профиль; зависимый от высоты FOV затем
ограничивает видимую область. Шаг Y задаётся как `speed/profile_rate`.
Поверхности преобразуются в координаты ленты; упрощённые два встречных взгляда
оставляют видимые верхние и боковые точки; z-buffer хранит не более одной глубины
на ячейку X/Y. Нижняя поверхность отсутствует. Затем моделируются собственные
тени, шум, пропуски точек, неполная видимость, пропуски целых полос профилей и
ограничение FOV по высоте. Модель не воспроизводит реальные BRDF, laser speckle, multipath,
насыщение или преломление прозрачной упаковки и не является Gocator Emulator.
Закрытая шестигранная поверхность используется только в низкоуровневых
регрессионных сценариях.

Размещение Monte Carlo считается до оптической модели по преобразованной
физической геометрии: для box/L/composite используются вершины экструдированного
контура, для cylinder — аналитические опорные направления окружности после полного
roll/pitch/yaw. Центр X выбирается только там, где экстремумы формы остаются в
`[-300; 300]` мм. Это отделяет физическую допустимость на ленте от последующего
оптического clipping. Тест независимо проверяет box 400×300 мм при yaw=45° на
обеих границах ленты.

Проекция на плоскость применяется только к нижнему 1% наблюдаемых точек. Это
box-friendly предположение о контакте с опорой, а не восстановление произвольного
скрытого дна или поднутрения.

Эталонные размеры хранятся в метаданных evaluator. Измеритель получает только точки и
замороженный `MeasurementConfig`; подмена скрытого эталона защищена тестом и не
меняет результат выполнения. L-призма, цилиндр и связный невыпуклый объект
проходят полный алгоритм.

Результаты разделены; их нельзя объединять в одно число «точности». Контрольные
наборы seed 42: regression — 7/7 correct OK, p95 abs L/W/H
`2,371 / 2,413 / 2,622 мм`; simplified line-profiler — 7/7 correct OK,
`4,675 / 2,570 / 1,311 мм`.

### Итог Monte Carlo

Всего я проверил 500 синтетических сценариев.

Метрики Monte Carlo считаются так:

- **Доля принятых:** `(correct OK + wrong OK) / expected-valid`;
- **Точность среди принятых:** `correct OK / (correct OK + wrong OK)`;
- **Доля корректных измерений:** `correct OK / expected-valid`.

| Monte Carlo subset | Total | Exp. valid | Exp. reject | Correct OK | Wrong OK | Rejected valid | Acceptance | Accepted precision | Correct rate |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| yaw-only | 125 | 125 | 0 | 121 | 2 | 2 | 98,4% | 98,4% | 96,8% |
| tilted/irregular | 125 | 125 | 0 | 93 | 11 | 21 | 83,2% | 89,4% | 74,4% |
| small-object | 125 | 125 | 0 | 119 | 0 | 6 | 95,2% | 100,0% | 95,2% |
| noisy/incomp. | 125 | 100 | 25 | 79 | 15 | 6 | 94,0% | 84,0% | 79,0% |
| **Итого** | **500** | **475** | **25** | **412** | **28** | **35** | **92,6%** | **93,6%** | **86,7%** |

Все 25/25 expected-reject сценариев отклонены; false accepted — 0. Это проверка
защитной логики на искусственном поднаборе, **не ожидаемая false-ok rate физической
станции**.

### Протокол заморозки

Порог расхождения OBB 25% сохранён как заранее выбранная инженерная эвристика;
после исправления физического размещения он не настраивался по финальному результату.
На development seed 1337 после исправлений получено 424 Correct OK, 25 Wrong OK
и 26 отказов среди 475 expected-valid: acceptance 94,5%, precision among accepted
94,4%, correct measurement rate 89,3%; 25/25 expected-reject отклонены.

Исправление изменило генератор случаев, поэтому прежняя финальная выборка
seed 20261017 стала недействительной. До просмотра нового результата параметры
были заморожены и назначен новый seed 20261018. На нём полный Monte Carlo 500
запущен один раз; после просмотра результата алгоритм и пороги не менялись.

### Что показал тест

На финальном tilted/irregular срезе получено 93 Correct OK, 11 Wrong OK и
21 reject/low-confidence: acceptance 83,2%, precision among accepted 89,4%,
correct measurement rate 74,4%. P95 абсолютной ошибки среди 104 принятых
status=ok: `14,520 / 10,619 / 2,962 мм`. Невидимая нижняя точка и поднутрения остаются
ограничением видимости упрощённого симулятора. Это указывает на потенциальную
проблему наблюдаемости, но не доказывает идентичный отказ физического dual-camera
Gocator; второй вид рассматривается только если реальный пилот подтвердит проблему.

![Рисунок 4. Результат симуляции измерения](../assets/demo/measurement.png)

На иллюстрации серым показана известная плоскость конвейера, синим — наблюдаемая
поверхность товара, красным — измеренный OBB. Большой пустой диапазон по X/Y нужен,
чтобы показать всю область 600-мм конвейера; визуально небольшой объект не
означает нехватку точек в исходном облаке. Отдельный `multiframe-demo` сохраняет
девять encoder-положений, пять валидных независимых окон, их медиану, итоговый
WMS JSON, PNG и GIF. Тест сверяет поля WMS с фактическим объединённым результатом.

В репозитории также сохранён `sample_scene.npz`, поэтому изображение не является
непроверяемой картинкой: CLI заново измеряет тот же формат и печатает WMS JSON.
Фиксированный seed обеспечивает повторяемость, но физическая приёмка намеренно
не опирается на этот генератор.

> Эти результаты проверяют программную геометрию на симулированных данных. Они не
> устанавливают абсолютную точность физической станции.

## 13. План физической валидации

После сборки станции я бы сначала проверил лазерную безопасность и работу без
товара, а затем измерил калибровочные блоки 10, 20, 50, 100, 300 и 400 мм.
Для каждой позиции нужны минимум 30 повторов в центре и по краям ленты, при разных
положениях и в разные дни. Для более формальной оценки можно провести MSA/Gage R&R
и отдельно оценить систематическую ошибку, линейность, повторяемость и
воспроизводимость.

После калибровочных объектов нужен тест не менее чем на 1000 реальных SKU:
по 10 проходов с разными углами, отдельно включая чёрные, блестящие, прозрачные
и мягкие товары. Затем следует 8-часовой прогон, проверка сетевых сбоев и теневой
пилот на реальной линии. Главная метрика — доля товаров, у которых все три стороны
удовлетворяют условию
`|measured−reference|≤max(0.05×reference,5 mm)`. Дополнительно нужно смотреть
распределение ошибки по осям, долю отказов по материалам, false-ok на прозрачных
товарах, повторяемость, время обработки и дрейф калибровки.

Конкретные пороги по доле успешных измерений, false-ok и задержке нужно согласовать
с бизнесом до контрольного тестирования на заранее не просмотренной выборке.

## 14. Производительность и масштабирование

Текущий benchmark работает с небольшими облаками и проверяет прежде всего
корректность функций. При ещё не подтверждённых 1000 профилях/с и 1280 отсчётах
на профиль входной поток может достигать 1,28 млн исходных отсчётов в секунду,
а за 700 мм зоны — 896 тыс. отсчётов. При 800/500/380 Гц поток пропорционально
ниже, но уменьшается число продольных срезов. Поэтому рабочий адаптер должен
сразу отбрасывать точки вне ROI и уменьшать облако до построения выпуклой оболочки.
При одном товаре примерно раз в 3 с времени на обработку достаточно; отправка
в WMS выполняется отдельно от измерения.

Оптимизации по порядку: ROI X/Z в сенсоре, удаление невалидных профилей,
voxel/grid downsample с шагом не крупнее 0,5–1 мм для минимального SKU,
постепенная кластеризация, выпуклая оболочка только объекта, ограничение числа
обрабатываемых окон и профилирование.
Уменьшать сетку сильнее 1 мм до отдельного исследования нельзя: можно потерять
реальный 10-мм объект и границу допуска.

## 15. Вывод и решение о следующем этапе

В результате выбран один Gocator 2880. Он покрывает область 600×300 мм,
даёт достаточную дискретизацию 10-мм объекта и уменьшает окклюзии двумя камерами
без взаимной калибровки двух отдельных голов. Один Gocator 2490 остаётся
работоспособным запасным вариантом, но пара 2490 слишком усложняет станцию.
Три 2450 дают избыточную точность, а для двух D457 нет достаточной опубликованной
метрологической гарантии.

Программный PoC показал, что полный путь от облака точек до WMS-сообщения
воспроизводится на синтетических сценариях. Для tilted/irregular acceptance rate
равен 83,2%, precision among accepted — 89,4%, correct measurement rate — 74,4%.
Это ограничение видимости упрощённого симулятора, а не доказанный предел
физического двухкамерного Gocator.

Физически ещё нужно подтвердить 1000 profiles/s, абсолютную точность, работу
с чёрными, блестящими и прозрачными товарами, а также провести пилот и
MSA/Gage R&R. До этого прозрачные и зеркальные объекты должны оставаться
отдельным контролируемым потоком.

## Приложение. Код, воспроизведение и проверка

### Код и демонстрация

Репозиторий: [github.com/Leo0742/Conveyor-Dimensioning-Station](https://github.com/Leo0742/Conveyor-Dimensioning-Station)

В репозитории находятся исходный код прототипа, тесты, синтетические сценарии,
демо и инструкция по запуску.

### Как воспроизвести

```bash
uv sync --frozen --python 3.12
uv run pytest -q
uv run ruff check .
uv run conveyor-dimensioning demo --output-dir assets/demo --seed 42
uv run conveyor-dimensioning benchmark --output-dir assets/demo --seed 42
uv run conveyor-dimensioning sensor-benchmark --output-dir assets/demo --seed 42
uv run conveyor-dimensioning monte-carlo --output-dir assets/demo --count 500 --seed 20261018
uv run conveyor-dimensioning multiframe-demo --output-dir assets/demo --seed 42
uv run conveyor-dimensioning measure assets/demo/sample_scene.npz \
  --item-id synthetic-check --seed 42
uv sync --frozen --python 3.12 --extra open3d
uv run python scripts/compare_obb.py --output assets/demo/obb_comparison.json
uv run python scripts/generate_diagrams.py
uv run python scripts/build_report.py
```

### Что проверено

Синтетический прототип воспроизводимо проходит путь от облака точек до WMS JSON;
проверены автоматические тесты, базовые benchmark-сценарии, Monte Carlo на 500
сценариях и независимое сравнение приближённого OBB.

### Что ещё требует физической проверки

В проекте нет физического Gocator, стенда с конвейером, калибровочных образцов и реального
набора товаров. Поэтому результаты benchmark относятся только к синтетическому программному тесту. Характеристики
resolution, linearity и repeatability из datasheet производителя сами по себе не доказывают точность всей станции. Для
подтверждения требуемой погрешности нужен физический пилот и MSA. До этого результаты нельзя считать
производственной гарантией.
