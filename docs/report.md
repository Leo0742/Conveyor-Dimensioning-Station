# Программно-аппаратный комплекс измерения габаритов товара на конвейере

**Болбачан Леонид Анатольевич**

## 1. Резюме решения

### Коротко о решении

- **Сенсор:** один двухкамерный лазерный профилометр LMI Gocator 2880.
- **Обработка:** локально на промышленном компьютере OnLogic Karbon K801.
- **Покрытие:** расчётное поле зрения 680 мм на уровне верхней грани товара. Это даёт запас по 40 мм с каждой стороны ленты.
- **Сканирование:** расчётная частота 1000 профилей в секунду. Её ещё нужно проверить на реальном датчике.
- **Интеграция:** передача результата в складскую систему (WMS). При сбое сети сообщение сохраняется в локальной очереди.

Цель станции — оценить три стороны минимального по объёму охватывающего
прямоугольного параллелепипеда. Координата X идёт поперёк ленты, Y — по движению,
Z — вверх от плоскости ленты. Товар обнаруживает ретрорефлекторный датчик
SICK WLF4FI-973121A0ZZZ (далее WLF4FI). Инкрементальный энкодер
SICK DFS60I-BHPC65536 (далее DFS60) с мерным колесом должен подавать аппаратные
импульсы с целевым шагом 1 мм после проверки допустимой частоты профилей.
Gocator 2880 объединяет данные двух камер и передаёт профили на вычислитель по
Ethernet. OnLogic Karbon K801 переводит точки в координаты ленты, удаляет фон,
объединяет профили и рассчитывает размеры товара. Для этого строится OBB —
ориентированный параллелепипед, который охватывает товар и не привязан к направлению
ленты. После проверки качества результат записывается в JSON и передаётся в WMS.

В основном сценарии машинное обучение не требуется: между товарами около 3 с, а
входной датчик и отделение точек от плоскости позволяют выделить товар без нейросети.
Она понадобится
только в том случае, если пилот обнаружит перекрытия, руки оператора, свисающую
упаковку или сложный движущийся фон.

Числа в документе разделены по происхождению:

- **По данным производителя** — официальная документация производителя;
- **Мой расчёт** — расчёт из опубликованных спецификаций и геометрии задачи;
- **Результат симуляции** — результат запуска данного прототипа;
- **Предварительная оценка** — оценка, которую надо подтвердить испытанием;
- **Физическое измерение** — результат испытания собранной станции; таких данных в проекте пока нет.

## 2. Требования и критерии приёмки

Исходный PDF [1] задаёт ленту 600 мм, скорость 1 м/с, средний интервал между
товарами 3 с, диапазон от 10×10×10 до 400×300×300 мм и допустимую ошибку каждой стороны
`±max(5 %, 5 мм)`. Форма и внешний вид произвольны. Результат передаётся в WMS.

| Параметр | Требование | Проверка проекта |
|---|---:|---|
| Ширина ленты | 600 мм | поле зрения 680 мм на высоте 300 мм; запас по 40 мм с каждой стороны |
| Скорость | 1000 мм/с | расчётный шаг между профилями 1 мм; частоту 1000 профилей/с нужно проверить |
| Поток | примерно 1 товар / 3 с | обработка выполняется локально; отправка в WMS не задерживает измерение |
| Минимум | 10×10×10 мм | около 10 профилей вдоль движения и 12,7 точки поперёк объекта |
| Максимум | 400×300×300 мм | диапазон по высоте 800 мм и зона длиной 700 мм |
| Допуск | ±max(5%, 5 мм) | расчёт отдельно по каждой сортированной стороне |
| Геометрия | параллелепипед минимального объёма | приближённый расчёт ориентированного параллелепипеда (OBB) |
| Интеграция | WMS | прототип формирует JSON и сохраняет сообщения в локальную очередь |

Для стороны 10 мм допустимо ±5 мм; для 100 мм — также ±5 мм; для 400 мм — ±20 мм.
Начальный инженерный ориентир может быть строже внешнего допуска, чтобы оставить
запас на дрейф, оптику, движение и алгоритм. Отдельное требование к 95-му
процентилю ошибки в исходном задании не указано. Его можно согласовать после
физического пилота.

## 3. Почему я не выбрал два Gocator 2490

В предварительном варианте я рассматривал два датчика 2490 из-за их широкого поля зрения.
Для сравнения я проверил не только заявленное разрешение,
но и шаг точек в рабочей геометрии. У 2490 шаг меняется с расстоянием, одна камера
создаёт тень, а два независимых сенсора требуют временной синхронизации, общей
системы координат, сшивания зон перекрытия и контроля взаимного дрейфа.

Расчёт показывает, что у 2490 достаточно точек даже при широком поле зрения.
При требуемой геометрии у ленты получается примерно 0,519 мм на точку, то есть
около 19,3 отсчёта на 10 мм. Это достигается за счёт 1920 точек в профиле [5].
Проблема не в дискретизации: одна камера даёт тени, а покупать вторую голову только
ради дополнительного ракурса слишком сложно и дорого. Кроме того, диапазон измерения 1525 мм для
этой задачи избыточен.

## 4. Сравнение оборудования

### 4.1 Правила сравнения

Разрешение, повторяемость, линейность и абсолютная точность — разные характеристики.
Разрешение показывает шаг между соседними точками, повторяемость — разброс при
повторных измерениях, а линейность — изменение ошибки по рабочему диапазону.
В изученных спецификациях LMI нет гарантированной абсолютной погрешности трёх
готовых размеров после монтажа, движения товара и обработки данных. Поэтому одной строки
из спецификации недостаточно: станцию нужно проверить на калибровочных объектах
с известными размерами и провести анализ измерительной системы (MSA/Gage R&R).

Для профилометра при скорости `v=1000 мм/с` шаг вдоль ленты равен
`ΔY = v / f`, где `f` — частота профилей. При 1000/800/500/380 Гц это соответственно
1,0/1,25/2,0/2,63 мм. При выдержке 1 мс товар успевает сместиться на 1 мм.
Частота сканирования и выдержка — разные параметры; выдержку нужно подобрать
на реальных тёмных и блестящих товарах.

### 4.2 Gocator 2880 — один двухкамерный профилометр

**По данным производителя.** LMI описывает 2880 как двухкамерный лазерный
профилометр с 1280 точками на профиль [3]. В спецификации версии 2.3 указаны:
поле зрения 390–1260 мм, разрешение по X 0,375–1,1 мм, разрешение по Z 0,092–0,488 мм,
диапазон измерения 800 мм, рабочее расстояние 350 мм, линейность по Z ±0,04% диапазона, частота
380–5000 Гц, входы энкодера и триггера, Ethernet 1 Гбит/с [4]. Отдельного значения
повторяемости в этой спецификации нет.

**Мой расчёт.** Для предварительной компоновки я использовал линейную
интерполяцию поля зрения между границами рабочего диапазона:

`FOV(z)=390+(1260−390)×z/800`.

Для запаса по 40 мм с каждой стороны я принял поле зрения 680 мм на уровне верхней
поверхности товара. Расстояние от начала рабочего диапазона до этой поверхности
равно `z_top≈266,67 мм`. Центр сенсора находится на
`350+266,67+300≈916,67 мм` над лентой. Плоскость ленты лежит на
`z≈566,67 мм`, где поле зрения ≈1006,25 мм. Максимальный шаг по X
`1006,25/1280≈0,786 мм`, то есть 10 мм занимают ≈12,72 отсчёта. На вершине
шаг равен ≈0,531 мм. При целевом шаге энкодера 1 мм получается около 10 профилей
вдоль объекта размером 10 мм. Диапазон измерения оставляет около 233,33 мм запаса ниже уровня ленты.
Линейность по Z `±0,04%×800 = ±0,32 мм` — это не абсолютная точность станции.

1000 профилей/с — **расчётная частота**, а не проверенный режим. По документации
LMI максимальная частота зависит от размера области сканирования и выдержки.
Если импульсы энкодера приходят слишком часто, датчик может пропускать их [26–29].
Проверить режим в фирменной программе LMI я не смог: она доступна только для
Windows и требует учётную запись LMI. Поэтому перед закупкой частоту нужно
подтвердить у поставщика или на стенде.

| Частота | Шаг Y | Профилей на 10 мм | Вывод для товара 10 мм |
|---:|---:|---:|---|
| 1000 Гц | 1,00 мм | 10 | хороший запас; нужно проверить в программе LMI или на датчике |
| 800 Гц | 1,25 мм | 8 | рабочий запас сохраняется |
| 500 Гц | 2,00 мм | 5 | погранично для устойчивых границ |
| 380 Гц | 2,63 мм | 3,8 | запас недостаточен для уверенного измерения |

До закупки оборудования нужно выбрать окончательную область сканирования и
выдержку, а затем подтвердить частоту 1000 Гц в программе LMI или на реальном
Gocator 2880. Если датчик не сможет работать в этом режиме, нужно проверить
800 Гц и пересчитать шаг вдоль ленты.

Две внутренние камеры видят одну лазерную линию с противоположных сторон и
уменьшают затенение от вертикальных стенок. Один корпус не требует внешней
синхронизации и взаимной калибровки двух голов. Верхняя система всё равно не
видит дно и глубокие поднутрения.

### 4.3 Gocator 2490 — одна или две головы

**По данным производителя.** Для 2490 указаны 1920 точек на профиль,
поле зрения 390–2000 мм, разрешение по X 0,25–1,1 мм, рабочее расстояние 350 мм,
диапазон измерения 1525 мм, линейность по Z ±0,04% диапазона, повторяемость 0,012 мм и 370 Гц на полном поле;
официальная продуктовая страница отдельно приводит 800 Гц для области 1×2 м
и до 5000 Гц [5, 6]. В англоязычной спецификации нет отдельной строки с
разрешением по Z, а в японской версии LMI указано 0,06–1,5 мм [30].

**Мой расчёт.** Для поля зрения 680 мм на высоте 300 мм `z_top≈274,69 мм`; высота
установки получается ≈924,69 мм. На ленте поле зрения ≈996,72 мм, шаг ≈0,519 мм и ≈19,26 отсчёта
на 10 мм. При 800 Гц продольный шаг равен 1,25 мм, то есть получается около
восьми профилей на 10 мм. Рабочий диапазон покрывает 300 мм с
большим запасом. Линейность по Z в абсолютных единицах равна ±0,61 мм, а
повторяемость — 0,012 мм. Складывать эти значения или называть их абсолютной
точностью нельзя.

Одна голова даёт один ракурс и выраженную тень. Две противоположные головы
уменьшают её, но требуют фирменного модуля синхронизации, распределения сигнала
энкодера и общей калибровки [9]. Цена и число возможных
точек отказа примерно удваиваются, а проблема прозрачных материалов остаётся.
Поэтому один 2490 подходит как запасной вариант, но два 2490 для этой геометрии
неоправданны.

### 4.4 Три Gocator 2450 — узкое поле

**По данным производителя.** Gocator 2450 имеет 1800 точек на профиль,
поле зрения 145–425 мм, разрешение по X 0,10–0,255 мм, рабочее расстояние
270 мм, диапазон измерения 550 мм, линейность по Z ±0,01% диапазона,
повторяемость 0,002 мм и частоту до 5000 Гц [7, 8].

**Мой расчёт.** Одна голова не покрывает 600 мм. Двух также недостаточно:
чтобы плоскость ленты оставалась в рабочем диапазоне при высоте товара 300 мм,
верхний срез можно поставить не дальше 250 мм от его начала. Там поле зрения
составляет около 272 мм, поэтому два датчика дадут примерно 545 мм
даже без перекрытия. Практически нужны минимум три головы, каждой около 220 мм
полезного поля с перекрытием. Получается больше 39 отсчётов на 10 мм, а линейность
по Z составляет ±0,055 мм. Это намного лучше требуемого, но объединение трёх систем, направленные
тени и высокая цена не окупаются допуском 5 мм.

### 4.5 Две RealSense D457 — активное стерео

**По данным производителя.** D457 имеет глобальный затвор, строит карту глубины
1280×720 и работает с частотой до 90 кадров/с. Поле зрения составляет 87°×58°,
рекомендуемый диапазон — 0,6–6 м, а минимальное расстояние — 0,52 м.
Заявленная погрешность глубины составляет менее 2% на расстоянии 4 м [11]. Производитель
также описывает аппаратную синхронизацию нескольких D457 и работу камер с
перекрывающимися областями [12, 13].

**Мой расчёт и инженерная оценка.** При монтаже камеры примерно в 0,8 м над
лентой поле на плоскости ленты ≈1518 мм, то есть ≈1,19 мм на пиксель и ≈8,4 пикселя
на 10 мм. Верх 300-мм товара находится уже примерно в 0,5 м: геометрическое
поле там ≈949 мм, но расстояние немного меньше указанного производителем минимума 0,52 м.
Поэтому расчёт на 0,8 м нельзя переносить на весь рабочий объём: высоту установки
и качество глубины пришлось бы проверять отдельно. При 90 кадрах/с объект проходит
11,1 мм между кадрами; нужна точная фаза триггера, а для товара минимального размера
нет запаса по числу кадров.
Две диагональные камеры сокращают слепые зоны, но требуют объединения карт глубины.
Опубликованная характеристика <2% на 4 м не является гарантией ≤5 мм для всей
измерительной станции в нашем рабочем диапазоне. Поэтому соответствие требованию
`±max(5%, 5 мм)` нельзя доказать по публичной спецификации D457. Активное стерео
чувствительно к слабой или повторяющейся текстуре, внешнему ИК-излучению,
чёрным, бликующим и прозрачным поверхностям. Этот вариант подходит для недорогого
лабораторного прототипа, но для станции я его не выбрал.

### 4.7 Закупка, сервис и запасной вариант

Точные цены и сроки можно узнать только из коммерческого предложения. Для 2880 и
2490 используется одна линейка оборудования Gocator и общая поддержка производителя;
для одного 2880 нужен один запасной датчик, а пара 2490 увеличивает число узлов,
синхронизацию и объём повторной калибровки. Три 2450 имеют повышенный риск замены
из-за трёх согласованных каналов. D457 продаётся как промышленная стереокамера,
но для неё нужны совместимый вычислитель, модуль приёма видеосигнала и драйвер [11]. Во всех случаях
наличие, срок и локальный сервис надо подтвердить у поставщика.

Если 2880 будет недоступен, первый запасной вариант — один 2490 при приемлемых
тенях на пилоте. Если одной камеры окажется недостаточно, можно перейти к двум
синхронизированным 2490.
Замена сенсора требует новой калибровки и повторной проверки измерений, а не только пересчёта поля зрения.

Чёрная матовая поверхность уменьшает отражённый сигнал, глянцевая может дать
насыщение и пропуски из-за бликов, а прозрачная — вернуть фон или несколько поверхностей. У 2880
две камеры повышают вероятность валидного отражения, но не решают физику материала.
Для рабочей линии нужно подобрать выдержку и мощность лазера, использовать матовый фон ленты
и контроль полноты данных; прозрачный товар при недостаточной полноте отправляется
на ручной поток.

### 4.8 Применение Gocator 2880 для упаковки

Выбор 2880 основан не только на таблице характеристик. В официальном анонсе LMI относит
его к задачам с упаковкой и крупными сложными формами, подчёркивая две камеры для
уменьшения слепых зон [23]. В примере измерения пустого объёма внутри коробки Gocator 2880
измеряет внутренний объём высоких коробок; два взгляда помогают видеть зоны,
которые закрывались бы одной камерой [24, 25]. Для задания важны те же физические
свойства: две камеры, поле зрения, диапазон измерения, частота сканирования,
энкодер/триггер, Ethernet и дискретизация. Gocator 2490 прямо позиционируется
для логистики и остаётся допустимым запасным вариантом, но его единственная
камера сильнее затеняет произвольную форму.

## 5. Предварительная компоновка станции

Все координаты этого раздела — **предварительный расчёт компоновки**. Поле зрения
680 мм на уровне верхней грани товара оставляет по 40 мм запаса с каждой стороны
600-мм ленты. Заводская
модель конкретного датчика и механические допуски должны уточнить координаты.

![Рисунок 1. Размещение оборудования, вид сбоку](../assets/diagrams/layout_side.png)

Сенсор предлагается установить по центру поперечной балки примерно в 916,7 мм над верхней
поверхностью ленты; лазерная линия ориентирована вдоль X. Товар движется по Y.
Расчётная зона накопления длиной 700 мм включает максимальные 400 мм товара и
запас до и после товара. WLF4FI стоит за 250 мм до начала зоны: при скорости 1 м/с
у системы будет 250 мс, чтобы получить `item_id`, проверить своё состояние и
подготовиться к записи профилей. DFS60 контактирует
с лентой мерным колесом; конкретный диаметр выбирается так, чтобы целочисленное
деление импульсов дало 1 мм и не превысило 820 кГц [14].

WLF4FI пока выбран только на основе характеристик, но его работа с товаром
10×10×10 мм ещё не проверена. В спецификации указан точечный ИК-луч и пятно около
Ø40 мм на 1 м [16]; результат зависит от расстояния, рефлектора, положения и
отражательной способности товара. Минимальные матовые, чёрные, блестящие и
прозрачные товары нужно проверить на стенде. Если датчик не справится, можно
изменить геометрию установки, выбрать меньшее световое пятно, поставить световую
завесу или определять присутствие товара по контроллеру линии (PLC) либо потоку профилей. Без такого
теста нельзя гарантировать надёжное срабатывание триггера.

![Рисунок 2. Размещение оборудования, вид сверху](../assets/diagrams/layout_top.png)

Кожух исключает доступ к лучу класса 3R и паразитную засветку; блокировка отключает
лазер при открытии. Механика должна иметь жёсткую базу, виброустойчивое крепление,
защиту окна и сервисный доступ. Расчётную высоту 916,7 мм нельзя сразу переносить
в монтаж: формула использует линейную интерполяцию крайних значений поля зрения, поэтому
нужна заводская калибровочная модель.

Калибровка включает шесть шагов: загрузку заводской модели профиля; перевод
координат датчика в координаты ленты; определение плоскости Z=0; настройку
масштаба и направления энкодера; измерение задержки от сигнала до профиля;
проверку по сертифицированным блокам в центре и по краям поля зрения.
Все функции прототипа предполагают уже калиброванные координаты: X поперёк ленты,
Y по движению, Z по нормали, а плоскость ленты находится около Z=0. Произвольные
некалиброванные мировые координаты не поддерживаются.

## 7. Алгоритм рабочей станции

1. WLF4FI обнаруживает товар и связывает измерение с `item_id` от PLC/WMS.
2. DFS60 должен аппаратно задавать Y каждой лазерной линии с целевым шагом 1 мм;
   этот режим включается только после проверки доступной частоты и пропусков триггеров.
3. Gocator 2880 формирует метрические X-Z профили из двух камер.
4. Заводская модель и внешняя калибровка переводят точки в координаты ленты.
5. На пустой ленте определяется её плоскость. Затем алгоритм проверяет её положение с помощью RANSAC.
6. Точки ниже минимальной высоты удаляются; выбросы фильтруются по соседям.
7. Радиус кластеризации я выбираю автоматически по расстоянию между соседними
   точками и ограничиваю диапазоном 2–20 мм. Мелкие шумовые компоненты
   отбрасываются; близкий фрагмент соединяется только если он не больше 20%
   соседнего компонента. Два близких сопоставимых компонента не сливаются;
   два кластера размером не менее 20% крупнейшего дают `object_overlap`.
8. Профили объединяются по координате Y, полученной от энкодера. Структура
   `AcquisitionBatch` хранит точки, шаг энкодера, число профилей, пропуски и
   признаки ошибок. Реального драйвера датчика в прототипе нет.
9. Строится приближённый ориентированный параллелепипед (OBB). Основное направление
   определяется по верхней плоскости товара. Дополнительно считается OBB
   по выпуклой оболочке. Если два способа дают слишком разные размеры, результат
   помечается как ненадёжный.
10. Размеры OBB сортируются `L≥W≥H`, после чего проверяются допустимый диапазон и
    простой показатель качества. Эти имена означают порядок рёбер, а не
    оси конвейера. Отдельно компоновка ограничивает физический вертикальный Z
    значением 300 мм. Если в реальной WMS поле `height_mm` должно точно совпадать
    с осью Z, понадобится отдельное правило преобразования вместо сортировки.
11. В прототипе только окна со статусом `ok` входят в расчёт медианы и MAD
    (медианного абсолютного отклонения) по каждой стороне.
    Итог `ok` требует минимум 3 таких окна, не менее 50% валидных окон и
    `MAD_axis ≤ max(2,5 мм; 2,5% × median_axis)`. Иначе при наличии геометрии
    возвращается `low_confidence`; если валидных окон нет —
    `insufficient_depth_data`. Окна с ошибкой не участвуют в расчёте медианы.
12. Прототип сохраняет сообщение в локальной JSONL-очереди, куда записи только добавляются; ограниченная
    очередь, подтверждение доставки и повторы относятся к будущей рабочей системе.

Иными словами, алгоритм сначала собирает точки одного товара, удаляет ленту и шум,
а затем отделяет сам товар. Если в зоне находятся два объекта или данных мало,
размеры не выдаются. Для одного объекта строится OBB, результаты нескольких окон
объединяются, и только после проверки стабильности формируется сообщение для WMS.

## 8. Почему я использовал OBB, а не AABB или PCA

AABB — это параллелепипед, стороны которого всегда направлены вдоль осей конвейера.
При повороте прямоугольной коробки на 45° его
границы по X и Y увеличиваются. PCA находит направления максимальной дисперсии,
но не минимизирует
объём; он нестабилен у симметричных и неполных поверхностей. Требование задания —
минимальный по объёму охватывающий прямоугольный параллелепипед.

Основной способ оценивает ориентацию по доминирующей верхней плоскости и ищет
прямоугольник минимальной площади в этой плоскости. Дополнительно считается OBB
по выпуклой оболочке через `scipy.spatial.ConvexHull` [20]. Для граней и рёбер
перебираются ортонормированные системы координат, после чего выбирается наименьший
из найденных объёмов. Если два способа дают расхождение больше 25%, результат
получает статус `low_confidence`.

Для независимой проверки я сравнил свой результат с библиотекой Open3D 0.19.0 на коробках,
L-образной фигуре, цилиндре и нескольких нерегулярных объектах. Метод
`create_from_points_minimal` в этой версии Open3D тоже даёт приближённый
результат; точный `MINIMAL_JYLANKI` здесь недоступен [18, 22]. Поэтому я не
называю ни один из результатов математически точным минимумом.

Оценка контакта с лентой — отдельная эвристика. На плоскость проецируется
только нижняя полоса (1-й процентиль), а не весь силуэт. Это помогает коробчатым
объектам оценить контакт и не раздувает наклонённый силуэт. Эвристика не
восстанавливает произвольное дно; ножки, полости, мягкая упаковка и невыпуклые
поднутрения остаются источником неопределённости.

Перед физической приёмкой нужно сравнить это приближение с более точной реализацией.
Если разница заметно влияет на допуск, алгоритм расчёта OBB придётся заменить.

## 9. Когда может понадобиться нейросеть

В основном алгоритме нейросеть не нужна. Если на реальной линии появятся руки
оператора, второй товар, свободный пакет или сложный фон, я бы добавил обычную
цветную камеру и сегментацию объектов. Основной класс — товар; отдельно нужно
размечать человека, руки, элементы конвейера и посторонние предметы. Маска нужна
только для выбора соответствующих 3D-точек; размеры всё равно вычисляются
геометрически.

Для пилота потребуется примерно 12–15 тыс. размеченных кадров или профильных
проекций: не менее 2 тыс. трудных примеров (чёрный, глянец, прозрачность, тонкие
пакеты, край поля зрения), 2 тыс. кадров без товара или с помехами и проходы одних
и тех же товаров под разными углами.
Разделение 70/15/15 выполняется группами по SKU, дню и линии, чтобы один экземпляр
не попал одновременно в обучение и тест. Аугментации включают яркость, шум,
смаз по движению, пропуски полос, частичную окклюзию и замену фона. Геометрический
масштаб нельзя менять без такого же преобразования карты глубины.

В качестве первой модели я бы попробовал YOLOv8m-seg, потому что в статье Ozon Tech
описывает переход к YOLOv8m-seg и более 15 тыс. изображений [2]. Это отраслевой
пример, а не результат этого проекта. При проверке модели важны качество маски,
результаты на сложных товарах, доля ложных объединений и разделений, а главное —
доля корректных измерений. Оптимизировать модель для промышленного компьютера
имеет смысл только после подтверждения её необходимости;
геометрический расчёт на CPU остаётся основным.

## 10. WMS и эксплуатационная надёжность

JSON содержит идентификаторы измерения и товара, время, три размера, показатель
качества и статус. В сообщении они называются `measurement_id`, `item_id`,
`timestamp`, `length_mm`, `width_mm`, `height_mm`, `confidence` и
`measurement_status`. Поле `confidence` — внутренний показатель качества, а не
вероятность правильности. `measurement_id`
стабилен для пары товар/время и используется для защиты от повторной записи. Пример:

```json
{
  "measurement_id": "36918523-5216-5204-acbf-cfde7c82fbdc",
  "item_id": "synthetic-demo-001",
  "timestamp": "2026-09-09T12:00:00Z",
  "length_mm": 120.781,
  "width_mm": 80.736,
  "height_mm": 45.966,
  "confidence": 0.968,
  "measurement_status": "ok"
}
```

**В прототипе реализованы:** схема сообщения, постоянный `measurement_id` для
одного события, время в UTC, локальная
JSONL-очередь и модульные тесты. Время без часового пояса отклоняется.

Для любого результата со статусом, отличным от `ok`, сообщение для WMS передаёт
`length_mm = width_mm = height_mm = null`: внутренние диагностические размеры
не представляются как доверенные измерения. Идентификаторы, время, показатель
качества и статус сохраняются.

В реальной системе сообщение можно отправлять в WMS по HTTPS, при необходимости
с взаимной проверкой сертификатов. Если WMS временно недоступна, результат должен остаться в локальной
очереди и отправиться повторно. Для внедрения также понадобятся аутентификация,
ограничение числа повторов, подтверждение доставки и контроль переполнения
очереди. Статус `wms_unavailable` относится к будущему модулю отправки
и не формируется текущим прототипом.

## 11. Ошибки и защитное поведение

### Основные отказы

| Сбой | Детектор | Поведение |
|---|---|---|
| нет или мало точек | число точек / отсутствие объекта | `insufficient_depth_data`, ручной поток |
| два товара | два сопоставимых кластера | `object_overlap`, не объединять размеры |
| объект вне диапазона | границы OBB, поля зрения и высоты | `measurement_out_of_range` |
| дрейф/вибрация | отклонение контрольной плоскости | `calibration_error`, останов/перекалибровка |
| мало окон или большой разброс | число окон и MAD по L/W/H | `low_confidence`, размеры не использовать |
| прозрачность или блики | контроль пропусков и насыщения | повтор с другой выдержкой или `low_confidence` |
| энкодер проскальзывает | расхождение скорости по данным PLC | отклонить результат, сервисное предупреждение |
| WMS недоступна | тайм-аут / 5xx | локальная очередь, подтверждение и повтор |
| персонал в зоне | световая завеса / блокировка | отключить лазер/остановить измерение |

### Статусы прототипа

| Статус | Реализован | Когда возникает | Что добавить в рабочей системе |
|---|---|---|---|
| `ok` | да | найден один объект, проверка качества пройдена | настроить показатель качества по физическому пилоту |
| `insufficient_depth_data` | да | нет измеримого объекта | другая выдержка или ручной поток |
| `object_overlap` | да | ≥2 значимых кластера | разделение потока через PLC |
| `measurement_out_of_range` | да | размер OBB выходит за допустимый диапазон | проверить границы поля зрения и высоты |
| `low_confidence` | да | <80 точек, расхождение двух OBB >25% или нестабильные окна | пороги проверить на физическом пилоте |
| `calibration_error` | частично | не найдена доминирующая плоскость | контроль калибровочного объекта |
| `wms_unavailable` | нет | только будущая передача | повтор и подтверждение |

Оптически невидимый выступ, дно и глубокая впадина принципиально не восстанавливаются
надёжно из верхнего вида. Если данных недостаточно, система должна отказаться от
измерения, а не выдавать сомнительный результат. Для
постоянного измерения полностью прозрачной упаковки нужен отдельный физический
канал (например, световая завеса или несколько силуэтных камер), новое сравнение
оборудования и новая проверка измерений.

## 12. Прототип и тестирование

В прототипе я использовал NumPy для хранения и обработки облака точек. SciPy
нужен для поиска соседей и построения выпуклой оболочки. Pydantic проверяет
структуру сообщений, передаваемых в WMS. Matplotlib и Pillow используются только
для визуализации демо, а ReportLab — для воспроизводимой сборки PDF-отчёта.
Open3D не входит в обязательные зависимости основного алгоритма: он нужен только
для независимого сравнения результата OBB.

Основной генератор — это **упрощённая симуляция лазерного профилометра**. Число
точек не задаётся произвольно: шаг X рассчитывается по полю зрения и 1280 точкам
на профиль. Поле зрения меняется с высотой и ограничивает видимую область.
Шаг Y равен скорости ленты, делённой на частоту профилей.
Поверхности преобразуются в координаты ленты; упрощённые два встречных взгляда
оставляют видимые верхние и боковые точки; z-буфер хранит не более одной глубины
в одной ячейке X/Y. Нижняя поверхность отсутствует. Затем моделируются собственные
тени, шум, пропуски точек, неполная видимость, пропуски целых полос профилей и
ограничение поля зрения по высоте. Модель не воспроизводит все оптические эффекты
реального датчика: свойства отражения материала, лазерный шум, переотражения,
насыщение и преломление в прозрачной упаковке. Это не фирменный эмулятор Gocator.
Закрытая шестигранная поверхность используется только в низкоуровневых
регрессионных сценариях.

Положение товара в серии случайных испытаний рассчитывается до оптической модели. Для коробки,
L-призмы и составной формы используются вершины выдавленного контура, а для
цилиндра — опорные направления окружности после поворота по трём осям. Центр X
выбирается только в тех положениях, где крайние точки формы остаются в диапазоне
`[-300; 300]` мм. Так я отделяю допустимое положение товара на ленте от обрезания
точек оптической моделью. Отдельный тест проверяет коробку 400×300 мм с поворотом
45° у обеих границ ленты.

На плоскость проецируется только нижний 1% наблюдаемых точек. Такое предположение
хорошо работает для коробок, но не восстанавливает произвольное скрытое дно или
поднутрения.

Эталонные размеры хранятся только в модуле оценки. Сам измеритель получает точки
и зафиксированный `MeasurementConfig`, но не знает правильный ответ. Тест отдельно
проверяет, что подмена эталона не меняет результат измерения. L-призма, цилиндр
и связный невыпуклый объект проходят полный алгоритм.

Эти результаты нельзя объединять в одно число «точности». На контрольных наборах
с начальным значением генератора 42 тест дал 7 из 7 корректных результатов со
статусом `OK`. В 95% случаев абсолютная ошибка L/W/H была не больше
`2,371 / 2,413 / 2,622 мм`. Упрощённая модель профилометра также дала 7 из 7
корректных `OK`, а граница для 95% ошибок составила
`4,675 / 2,570 / 1,311 мм`.

### Итог проверки на случайных сценариях

Всего я проверил 500 синтетических сценариев методом Monte Carlo, то есть с
разными случайными размерами, положениями, наклонами и помехами.

Показатели считаются так:

- **Доля принятых:** сколько допустимых сценариев завершились статусом `OK`;
- **Точность среди принятых:** какая часть результатов `OK` уложилась в допуск;
- **Доля корректных измерений:** какая часть всех допустимых сценариев и была
  принята, и уложилась в допуск.

| Группа | Всего | Допуст. | Отклонить | Верных `OK` | Ошиб. `OK` | Отказов | Принято | Точность | Корректно |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Поворот на ленте | 125 | 125 | 0 | 121 | 2 | 2 | 98,4% | 98,4% | 96,8% |
| Наклон и сложная форма | 125 | 125 | 0 | 93 | 11 | 21 | 83,2% | 89,4% | 74,4% |
| Маленький товар | 125 | 125 | 0 | 119 | 0 | 6 | 95,2% | 100,0% | 95,2% |
| Шум и неполные данные | 125 | 100 | 25 | 79 | 15 | 6 | 94,0% | 84,0% | 79,0% |
| **Итого** | **500** | **475** | **25** | **412** | **28** | **35** | **92,6%** | **93,6%** | **86,7%** |

Все 25 сценариев, которые должны были завершиться отказом, действительно
отклонены; ложных `OK` среди них нет. Это только проверка защитной логики на
искусственном поднаборе, **а не оценка частоты ошибок физической станции**.

### Как я зафиксировал параметры перед итоговым запуском

Порог расхождения двух способов расчёта OBB в 25% я выбрал заранее. После
исправления физического размещения я не настраивал его по итоговому результату.
На рабочем наборе с начальным значением генератора 1337 после исправлений получено 424 корректных `OK`, 25 ошибочных
`OK` и 26 отказов среди 475 валидных сценариев. Доля принятых составила 94,5%,
точность среди принятых — 94,4%, доля корректных измерений — 89,3%. Все 25
сценариев с ожидаемым отказом были отклонены.

Исправление изменило генератор сценариев, поэтому результаты с начальным значением
20261017 стали недействительными. До нового запуска я зафиксировал параметры и
выбрал новое значение 20261018. Полный тест на 500 сценариях был запущен один раз;
после получения результата алгоритм и пороги не менялись.

### Что показал тест

На итоговом наборе наклонённых и нерегулярных объектов получено 93 корректных
`OK`, 11 ошибочных `OK` и 21 отказ или результат с низкой уверенностью. Доля
принятых составила 83,2%, точность среди принятых — 89,4%, а доля корректных
измерений — 74,4%. У 95% из 104 принятых результатов абсолютная ошибка не
превышала `14,520 / 10,619 / 2,962 мм` по трём сторонам. Невидимая нижняя часть
и поднутрения остаются
ограничением видимости упрощённого симулятора. Значит, часть формы может быть
плохо видна в модели, но это ещё не доказывает такую же проблему у физического
двухкамерного Gocator. Дополнительный ракурс стоит рассматривать только в том
случае, если проблема повторится на реальном пилоте.

![Рисунок 4. Результат симуляции измерения](../assets/demo/measurement.png)

На иллюстрации серым показана известная плоскость конвейера, синим — наблюдаемая
поверхность товара, красным — измеренный OBB. Большой пустой диапазон по X/Y нужен,
чтобы показать всю область 600-мм конвейера; визуально небольшой объект не
означает нехватку точек в исходном облаке. Отдельная демонстрация с несколькими
окнами сохраняет девять положений энкодера, пять подходящих независимых окон, их
медиану, итоговый WMS JSON, PNG и GIF. Тест сверяет поля WMS с фактическим
объединённым результатом.

В репозитории также сохранён `sample_scene.npz`. Эту сцену можно заново измерить
через командную строку и получить WMS JSON, поэтому результат на изображении воспроизводим.
Фиксированное начальное значение генератора позволяет повторить синтетический тест, но не заменяет
физическую приёмку.

> Эти результаты проверяют программную геометрию на симулированных данных. Они не
> устанавливают абсолютную точность физической станции.

## 13. План физической валидации

После сборки станции я бы сначала проверил лазерную безопасность и работу без
товара, а затем измерил калибровочные блоки 10, 20, 50, 100, 300 и 400 мм.
Для каждой позиции нужны минимум 30 повторов в центре и по краям ленты, при разных
положениях и в разные дни. Для более формальной оценки нужен анализ измерительной системы (MSA/Gage R&R)
и отдельно оценить систематическую ошибку, линейность, повторяемость и
воспроизводимость.

После калибровочных объектов нужен тест не менее чем на 1000 реальных SKU:
по 10 проходов с разными углами, отдельно включая чёрные, блестящие, прозрачные
и мягкие товары. Затем нужен 8-часовой прогон, проверка сетевых сбоев и пилотный
запуск параллельно с текущим процессом на реальной линии. Главная метрика — доля
товаров, у которых все три стороны
удовлетворяют условию
`|измеренное−эталонное|≤max(0,05×эталонное, 5 мм)`. Дополнительно нужно смотреть
распределение ошибки по осям, долю отказов по материалам, долю ошибочных `OK` на прозрачных
товарах, повторяемость, время обработки и дрейф калибровки.

Конкретные пороги по доле успешных измерений, ошибочных `OK` и задержке нужно согласовать
с бизнесом до контрольного тестирования на заранее не просмотренной выборке.

## 14. Производительность и масштабирование

Тест производительности работает с небольшими облаками и проверяет прежде всего
корректность функций. При ещё не подтверждённых 1000 профилях/с и 1280 отсчётах
на профиль входной поток может достигать 1,28 млн исходных отсчётов в секунду,
а за 700 мм зоны — 896 тыс. отсчётов. При 800/500/380 Гц поток пропорционально
ниже, но уменьшается число продольных срезов. Поэтому рабочий адаптер должен
сразу отбрасывать точки вне рабочей области и уменьшать облако до построения выпуклой оболочки.
При одном товаре примерно раз в 3 с времени на обработку достаточно; отправка
в WMS выполняется отдельно от измерения.

Оптимизации по порядку: ограничение рабочей области X/Z в сенсоре, удаление
неподходящих профилей, уменьшение плотности точек с шагом не крупнее 0,5–1 мм,
постепенная кластеризация, выпуклая оболочка только объекта, ограничение числа
обрабатываемых окон и профилирование.
Уменьшать сетку сильнее 1 мм до отдельного исследования нельзя: можно потерять
реальный 10-мм объект и границу допуска.

## 15. Вывод и решение о следующем этапе

В итоге я выбрал один Gocator 2880. Он покрывает область 600×300 мм,
даёт достаточное количество точек для объекта размером 10 мм и уменьшает слепые зоны двумя камерами
без взаимной калибровки двух отдельных голов. Один Gocator 2490 остаётся
работоспособным запасным вариантом, но пара 2490 слишком усложняет станцию.
Три 2450 дают избыточный запас, а для двух D457 по опубликованным характеристикам
нельзя подтвердить требуемую точность всей станции.

Программный прототип показал, что полный путь от облака точек до WMS-сообщения
воспроизводится на синтетических сценариях. Для наклонённых и нерегулярных
объектов доля принятых равна 83,2%, точность среди принятых — 89,4%, а доля
корректных измерений — 74,4%.
Это ограничение видимости упрощённого симулятора, а не доказанный предел
физического двухкамерного Gocator.

На физическом стенде ещё нужно подтвердить 1000 профилей/с, абсолютную точность, работу
с чёрными, блестящими и прозрачными товарами, а также провести пилот и
анализ измерительной системы. До этого прозрачные и зеркальные объекты лучше
направлять на отдельную ручную проверку.

## Приложение. Код, воспроизведение и проверка

### Код и демонстрация

Репозиторий: [github.com/Leo0742/Conveyor-Dimensioning-Station](https://github.com/Leo0742/Conveyor-Dimensioning-Station)

В репозитории находятся исходный код прототипа, тесты, синтетические сценарии,
демо и инструкция по запуску.

### Как воспроизвести

```bash
uv sync --frozen --python 3.12
uv run pytest -q
uv run ruff check .
uv run conveyor-dimensioning demo --output-dir assets/demo --seed 42
uv run conveyor-dimensioning benchmark --output-dir assets/demo --seed 42
uv run conveyor-dimensioning sensor-benchmark --output-dir assets/demo --seed 42
uv run conveyor-dimensioning monte-carlo --output-dir assets/demo --count 500 --seed 20261018
uv run conveyor-dimensioning multiframe-demo --output-dir assets/demo --seed 42
uv run conveyor-dimensioning measure assets/demo/sample_scene.npz \
  --item-id synthetic-check --seed 42
uv sync --frozen --python 3.12 --extra open3d
uv run python scripts/compare_obb.py --output assets/demo/obb_comparison.json
uv run python scripts/generate_diagrams.py
uv run python scripts/build_report.py
```

### Что проверено

Синтетический прототип проходит весь путь от облака точек до WMS JSON. Я проверил
автоматические тесты, базовые сценарии, 500 случайных сценариев Monte Carlo и отдельно
сравнил приближённый OBB с реализацией Open3D.

### Что ещё требует физической проверки

В проекте нет физического Gocator, стенда с конвейером, калибровочных образцов и
реального набора товаров. Поэтому результаты относятся только к синтетическому
программному тесту. Значения разрешения, линейности и повторяемости из
спецификации производителя сами по себе не доказывают точность всей станции.
Чтобы подтвердить требуемую погрешность, нужен физический пилот и анализ
измерительной системы (MSA). До этого
результаты нельзя считать производственной гарантией.
